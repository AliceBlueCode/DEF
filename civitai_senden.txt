> Dialogue × Emotion × Fable

> With your characters, for years to come, wherever you go.

-----

What is DEF(kari)?
DEF(kari) is a local-first AI creative platform that integrates text, voice, and image generation.

Rather than entrusting your creative content to the terms of service and content policies of cloud services, DEF(kari) provides the foundation for generating and sustaining the characters and stories you desire, in your own environment, with your own hands.

-----

No GPU? You can still get started.
DEF is local-first, but you don't need a local environment to begin.

Using external APIs (Gemini / OpenAI / Anthropic, etc.), text generation and voice synthesis work without a GPU. Image generation requires a T2I API (Civitai / Hugging Face) or a local GPU environment.

Once your local setup is ready, you can switch to fully offline, high-speed operation at any time.

Key Features
- Local-First: LLM, TTS, and T2I all run locally. External API fallback also supported

- No GPU required to start: Text + voice works via external APIs. Switch to local GPU whenever you're ready

- 3-Modality Integration: Text, voice, and image work together as a continuous creative experience

- 3 Modes: Chat (1-on-1 dialogue), Session (multiple AIs + humans at the same table), Episode (novel writing + AI candidate generation)

- Character Persistence: Dialogue history, emotions, and generated assets are persisted — resume from where you left off after restart

- Adapter Pattern: Freely swap between 4 LLM, 4 TTS, and 4 T2I backends

- Zoning: Clear separation of public and private data. Generated assets are excluded from Git

| TTS (voice) | VOICEVOX / Kokoro TTS / Irodori-TTS | Gemini TTS API |

| T2I (image) | Automatic1111 / ComfyUI | Civitai API / Hugging Face API |

Our Stance on Creative Freedom
Creators are free to create whatever they wish. However, creators bear full responsibility for their creations.

DEF(kari) is designed based on this principle.

When a tool preemptively intervenes in creative content, it infringes on the creator's freedom of expression. DEF(kari) does not censor or block content for local creative activities.

### Clear Separation of Public and Private

What DEF(kari) protects is the boundary between public and private, not the private creative act itself.

Private (local creation):

This is the domain where the creator's freedom is fully guaranteed. DEF(kari) does not intervene here at all. The safety filter (F-8) is merely a "display control tool" that users can turn off. It never prevents generation itself.

Public (publishing to GitHub or external platforms):

This is the domain where social rules, copyright, and public decency apply. DEF(kari) provides technical support through content_policy fields, zoning (F-16), and publication judgment scripts (F-25) to prevent creators from unintentionally publishing private content.

All judgment and responsibility regarding creative content, publication, and usage belong to the creator.

創作の自由についての考え方
クリエイターは自分が望むものを自由に創作してよい。ただし、創作物の責任はクリエイター自身が負う。

DEF(kari)はこの原則に基づいて設計されています。

ツールが創作の内容に先回りして介入することは、クリエイターの表現の自由を侵害します。DEF(kari)はローカル環境での創作行為に対してコンテンツを検閲・ブロックしません。

### パブリックとプライベートの明確な分離

DEF(kari)が守るのは**パブリックとプライベートの境界**であり、プライベートな創作行為そのものではありません。

プライベート(ローカル環境での創作):

クリエイターの自由が完全に保障される領域です。DEF(kari)はここに一切介入しません。セーフティフィルター(F-8)はあくまで「表示制御のツール」であり、ユーザーがオフにできます。生成そのものを止めることはしません。

パブリック(GitHubや外部への公開):

社会的なルール・著作権・公序良俗が適用される領域です。DEF(kari)content_policyフィールド・ゾーニング(F-16)・公開判定スクリプト(F-25)によって、クリエイターが意図せずプライベートなコンテンツを公開してしまわないよう技術的に支援します。

創作の内容・公開・利用に関する判断と責任は、すべてクリエイター自身に帰属します。

DEF v2.0.0 is not a feature update, but a system-level redefinition.

Structural constraints for feature scalability

Difficulty integrating Chat / Session / Novel modes

Complexity in external AI backend integration

Lack of long-term character continuity design

To address these issues, v2.0.0 introduces:

Full separation of frontend and backend

API-centric architecture

Unified foundation for multi-mode systems (Chat / Session / Novel)

System redesign centered on persistent character continuity

DEF v2.1.1
Persistent Character Platform

This release focuses on refinement rather than expansion.

-----

What changed in v2.1.1
-----

1. Character LoRA Management
Character profiles can now define LoRA settings that are automatically appended during T2I generation.

Characters define their own visual representation.

-----

2. Recursive Character Directory
Recursive traversal for DEF-Character's directory structure.

Characters can be organized across any number of hierarchy levels: Group → Subgroup → Character → and beyond.

-----

3. session_prompts.json — Externalized Session Instructions
Session LLM instructions have been moved to: data/session_prompts.json

Content, language, and tone can now be customized without modifying the source code.

-----

4. T2I Prompt Generation Modes
Three prompt generation modes are now available for Session and Novel.

Selectable from: Settings → Session Settings

| Mode | Behavior |

| current | Generate prompt from conversation history (default) |

| passthrough | Use image_prompt_en directly |

| dedicated | Generate a concise prompt using a dedicated system prompt (num_predict=128) |

-----

5. OpenAI TTS — Fifth Voice Backend
OpenAI TTS API (tts-1 / tts-1-hd) has been added.

Text and speech can now operate entirely through external APIs without requiring a local environment.

| Layer | Local | External API |

| TTS | VOICEVOX / Kokoro / Irodori | Gemini TTS / OpenAI TTS |

-----

6. Backend Folder Picker & Connection Test
Folder picker and connection test buttons have been added to backend settings.

Direct .env editing is no longer required for path configuration.

-----

7. Configurable Backend Polling Interval
status_poll_sec can now be configured from: Settings → Backend

(Default: 5 seconds)

-----

8. Bug Fixes
- Skip greeting and history clear when switching to the same character (F-26 v2.1.1+)

- Added --use_gpu when launching VOICEVOX

- Improved TTS name replacement order: Full Name → Given Name → Family Name

-----

GitHub: https://github.com/AliceBlueCode/DEF

DEF v2.1.1
Persistent Character Platform

今回は機能拡張ではなく、既存機能の完成度向上を目的としたリリースです。

-----

v2.1.1 の変更点
-----

1. キャラクターLoRA管理
キャラクタープロファイルにLoRA設定を記述し、T2I生成時に自動付加できるようになりました。

キャラクター自身が、自らのビジュアルを定義します。

-----

2. キャラクターディレクトリ再帰走査対応
DEF-Character のディレクトリ構造を再帰的に走査するようになりました。

グループ → サブグループ → キャラクター → さらにその下、と何階層でも整理できます。

-----

3. session_prompts.json — LLM指示文の外出し
セッション用LLM指示文を data/session_prompts.json へ移動しました。

コードを編集することなく、内容・言語・トーンを変更できます。

-----

4. T2Iプロンプト生成モード
Session・Novelタブに3種類の生成モードを追加しました。

設定タブのセッション設定から切り替えできます。

| モード | 動作 |

| current | 会話履歴から生成（デフォルト） |

| passthrough | image_prompt_en をそのまま利用 |

| dedicated | 専用システムプロンプトで短いプロンプトを生成 |

-----

5. OpenAI TTS — 第5の音声バックエンド
OpenAI TTS API (tts-1 / tts-1-hd) に対応しました。

ローカル環境がなくても、テキスト＋音声を外部APIだけで利用できます。

| レイヤー | ローカル | 外部API |

| TTS | VOICEVOX / Kokoro / Irodori | Gemini TTS / OpenAI TTS |

-----

6. バックエンド設定フォルダピッカー・接続テスト
各バックエンド設定に「フォルダピッカー」および「接続テスト」ボタンを追加しました。

.env を直接編集する必要がなくなりました。

-----

7. バックエンドポーリング間隔設定
status_poll_sec を、設定 → バックエンド から変更できます。

（デフォルト：5秒）

-----

8. Bug Fixes（バグ修正）
- 同一キャラクター切替時の挨拶・履歴クリアをスキップ（F-26 v2.1.1+）

- VOICEVOX起動時に --use_gpu を追加

- TTS読み替え順を フルネーム → 名 → 姓 に改善

-----
